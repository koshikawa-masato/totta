# totta

固定したカメラの前で書籍の見開きを開いて止め、めくる——それだけで**静止したページを自動で切り出して PDF にする** macOS / iOS アプリ。入力はライブカメラのみです。

## データ保持ポリシー

撮影データが流用されるリスクを避けるため、次の方針で作られています。

- **入力はライブカメラだけ**。動画ファイルの読み込み機能はありません(ドラッグ&ドロップも不可)。
- **カメラ映像は録画も一時保存もしない**(`AVCaptureMovieFileOutput` は使わない)。取り込んだページのフレームはメモリ上(JPEG エンコード済み `Data`)にだけ保持する。
- ディスクに書くのは **書き出した最終 PDF だけ**。サムネイルやクロップ結果を一時ファイルに書かない。
- **PDF の書き出しが完了した時点で、ページ・フレーム・サムネイルなど途中データはすべて破棄**する。「破棄」ボタンで手動でも捨てられる。

## 構成

```
Core/                     Swift Package(macOS 14+ / iOS 17+)
  Sources/TottaCore/
    Fingerprint.swift       動き検出・重複判定用の縮小指紋
    StillnessTracker.swift  逐次の静止判定(静止 → 取り込み → めくり検知 → 次)
    PageDetector.swift      Vision で見開き矩形を検出、CoreImage で台形補正クロップ
    PageCapture.swift       フレーム 1 枚 → ページ情報、重複判定(DuplicateFilter)
    LiveScanner.swift       AVCaptureSession を録画せず逐次解析し、静止ページだけ取り込む
    PageEnhancer.swift      紙面均一化(照明ムラ除去+レベル補正)と指・手の映り込み除去(CoreImage + Vision)
    PageOCR.swift           Vision によるオンデバイス OCR(日本語/英語)
    PDFExporter.swift       CGPDFContext で PDF 化(JPEG 圧縮、見開き左右分割、右綴じ、透明テキスト層、用紙サイズ)
    PDFPipeline.swift       1 ページずつ「展開 → 切り出し → 補正 → 分割 → OCR → 追記」する逐次書き出し
    MarkdownExporter.swift  OCR 結果をレイアウト解析(XY-cut)で読み順に並べ直し、段落にまとめて Markdown 化
  Tests/                  ユニットテスト + 合成フレーム列を流す取り込みフローのテスト
App/Totta/                SwiftUI アプリ(macOS / iOS 共通ソース)
project.yml               xcodegen 定義 → Totta.xcodeproj を生成
```

## ビルド

```sh
# Xcode プロジェクト生成(要 xcodegen: brew install xcodegen)
xcodegen generate
open Totta.xcodeproj          # スキーム Totta (macOS) / Totta-iOS

# コマンドラインでビルド
xcodebuild -project Totta.xcodeproj -scheme Totta -configuration Debug build

# Core のテスト
cd Core && swift test
```

### iPhone / iPad で使う(Totta-iOS)

1. Xcode に iOS プラットフォーム(シミュレータランタイム)を入れる: `xcodebuild -downloadPlatform iOS`(約 8GB)。SDK だけでは足りず、これが無いと実機向けにもビルドできません。
2. `xcodegen generate` → `open Totta.xcodeproj` → スキーム **Totta-iOS**、実機を選んで Run。または iPhone をロック解除して接続し `scripts/install-iphone.sh` を実行(ビルド → インストール → 起動まで自動)。`project.yml` の `DEVELOPMENT_TEAM` に自分の Team ID を設定してあります(Xcode の Signing & Capabilities でも変更可)。無料の Apple ID でも実機に入れられます(7 日ごとに再インストール)。
3. iPhone 側: 設定 > プライバシーとセキュリティ > デベロッパモード をオン。初回起動時に「VPN とデバイス管理」で開発者を信頼。
4. iPhone を三脚やスタンドで固定し、横向きに構えて使うと見開きが画面いっぱいに入ります。縦持ちでも `AVCaptureDevice.RotationCoordinator` でプレビューと取り込みの向きは自動で揃います。iPhone(コンパクト幅)ではカメラ画面がルートで、左上の「ページ」からページ一覧 → 編集へ進みます。書き出しは「ファイル」アプリへの保存になります。

Mac 版で iPhone を **連携カメラ(Continuity Camera)** として選ぶこともできます(1080p まで。追加設定不要)。

## 使い方

1. **ライブカメラで取り込む** を押す(初回はカメラの許可)。複数カメラがあれば上部で選択(iPhone の連携カメラも可)。この時点ではプレビューのみで、勝手に取り込みは始まりません。
2. 本を置いた状態で **プレビューをタップ** → その位置でピント・露出・ホワイトバランスを合わせて固定(黄色い枠が出ます。状態バーの錠アイコンが緑になれば固定済み)。
3. 右側の **「枠を合わせる」** を押すと、プレビューから静止画を 1 枚取り出して編集画面になる。四隅(青)を見開きの角に、のど線(オレンジ)を折り目に合わせて **「この枠で開始」**。この枠が基準枠として保存され、以降のページはすべてこの枠で切り出される(枠検出は行わない)。
4. ボタンが **「開始」** に変わるので押す(Space)。見開きを開いて **設定秒数(既定 0.7 秒)止める** → 自動で取り込み(画面が白くフラッシュ) → めくる、を繰り返す。「停止」でいったん止まる。

カメラ画面は映像を全画面に出し、操作は OSD にまとめてある。左に状態と直近サムネイル、右に主ボタン 1 つ。その他(ページ一覧・カメラ選択・ズーム・手動で 1 枚取り込み・枠を合わせる・設定・PDF 書き出し・カメラ停止)は **上端を下スワイプ**(または「⌄」)で出るバーにある。
5. 左のリストでページを確認。「前ページと酷似」の警告が出たものは除外するか判断する(「酷似を除外」で一括)。
6. 枠がずれていれば四隅をドラッグして調整。見開きは外枠 4 点+**のど線 2 点(オレンジ)**で表され、左右ページを別々に台形補正して並べる(のどで折れた本でも各ページがまっすぐになる)。「のど線」ボタンで単ページ扱いとの切り替え、「再検出」「全体」も使える。**「基準枠にする」**を押すと、その枠+のど線を基準枠として保存し、既存の全ページに適用したうえで、以降の取り込みでも枠検出をせずにこの枠を使う(カメラ固定向け。プレビューに点線で表示され、「解除」で自動検出に戻る。基準枠は座標だけをアプリ再起動後も保持)。「切り出し」タブで結果を確認。「カメラに戻る」で取り込みを続行。
7. 「補正後」タブで、紙面均一化と指除去の結果を確認できる(設定で調整・オフにできる)。
8. **PDF 書き出し**。ページごとに「展開 → クロップ → 補正 → (見開き分割) → OCR → 透明テキスト付き PDF に追記」の順で処理し、検索・コピーできる PDF になる。進捗表示から**キャンセル**でき、完成したら**プレビューで確認**してから保存する。保存が完了すると途中データは破棄され、次の本の取り込みに戻る。

### 書き出しの実装メモ

- **逐次書き出し**: `PDFBuilder` に 1 ページずつ書き足し、そのページの一時画像は `autoreleasepool` でその都度解放する。全ページを同時に展開しないので、ページ数を増やしてもメモリが積み上がらない(4032×3024 の見開きを流したベンチマークで 4→64 ページのピーク 215MB→540MB で頭打ち。全ページ同時展開なら 1 ページ 46MB × ページ数 + 補正結果でギガ単位になる)。
- **キャンセル**: `Task.checkCancellation()` をページ単位・分割単位で見ているので、書き出し中に止められる。
- **見開き分割(既定オン)**: 見開きを中央で割って 1 ページ 1 面で書き出す。見開きのまま 1 ページにすると、pdfminer など外部パーサのレイアウト解析が左右ページの行を交互に混ぜることがあるため(LLM に読ませる前提では致命的)。縦長(片ページ)の画像は分割しない。設定でオフにできる。
- **用紙サイズ**: 既定は画像の画素数と DPI から算出。A4/A5/B5/B6/レターを選ぶと、その用紙に縦横比を保って中央配置し、画像が横長なら用紙も横向きにする。
- ベンチマーク: `TOTTA_MEM=64 [TOTTA_OCR=1] swift test --filter ExportBenchmarkTests`

### 補正と OCR について

- **紙面均一化**: 画像を縮小して最大値フィルタ+ぼかしで「紙の明るさ」を推定し、元画像をそれで割ってから黒点/白点でレベル補正する。影・照明ムラが消え、OCR の前処理にもなる。
- **見開き検出**: Vision の矩形検出は折れた見開きを 1 つの四角形として拾えず片ページになりがちなので、(1) 検出結果から左右に隣接するもう 1 ページを探して結合、(2) 無ければ見つかったページを塗りつぶして再検出、(3) それでも片ページなら Apple の書類セグメンテーション(`VNDetectDocumentSegmentationRequest`、学習済み・オンデバイス)のマスクから残り側の 2 隅を求めて見開きを構成する。平らな本で見開き全体が 1 つの矩形として取れたときも横長なら中央にのど線を置く。左右ページは別々に補正して同じサイズに揃えて並べる(見開き分割の書き出しも中央で正確に割れる)。
- **グレースケール(既定オン)**: 本文スキャンに色は不要なので、書き出し時に DeviceGray の 1 チャンネル画像へ変換する。CoreImage の `photoEffectMono` は見た目がグレーになるだけで RGB のままなのでサイズが落ちない点に注意(実測 14 ページ: カラー 45.2MB / RGB のままグレー 35.8MB / 真のグレー 35.2MB)。JPEG 品質の既定は 0.75(同 29.4MB)。Claude に PDF を添付する上限が 32MB なので、既定でその範囲に収まるようにしてある。
- **出力解像度**: PDF に載せる画像の長辺を既定 2400px に縮小する(撮影は 4K のまま)。**OCR は縮小前のフル解像度で実行**してから縮小するので、認識精度を落とさずサイズだけ下げられる。縮小処理はグレースケールの色空間を維持する(RGB に戻すとサイズが 3 倍になるため)。実測(14 ページ・グレー q0.75): 撮影したまま 29.4MB / 3000px 18.6MB / **2400px 12.6MB** / 2000px 9.2MB / 1600px 6.2MB。2400px でも本文は問題なく読める。
- **カメラ**: 端末が持つ 30fps 以上のフォーマットのうち最大画素数(iPhone なら 4K/4032×3024 相当、上限 12.6MP)を既定で使う。ズームはスライダーまたはピンチ(iOS)。
- **向き**: 見開きは横長なので、既定で**画面(UI)ごと横向きに固定**する(`UIApplicationDelegate` の `supportedInterfaceOrientationsFor` と `requestGeometryUpdate` を使用)。端末を縦に持っていてもカメラ画面は横レイアウトで表示され、映像も**横向き(センサー本来の向き)のまま**取り込む(設定でオフ可)。プレビューと取り込みフレームには常に同じ回転角を適用するので、プレビュー上の基準枠と実際の切り出しが一致する。向きが変わって縦横比が合わなくなった基準枠は適用されず、自動検出に切り替わる。
- **指の除去(既定オフ)**: クリーム色の本文用紙は肌色と色相・彩度が近く、色だけで判定するとページ本体を「指」とみなして消してしまう(実際に初期実装で全ページの本文を破壊した)。そのため次をすべて満たす領域だけを消す: ①Vision で**手が検出され**その関節位置を含む連結領域、②紙より彩度が高い(紙の色は画像から推定)、③肌色の色相、④縦横どちらかがページの半分未満の細長い形、⑤全体の被覆率が上限(既定 10%)以下。ひとつでも外れたら**何も消さない**方に倒す。文字の上にかかった指も復元しない(生成 AI で文字を捏造しない方針)。
- **OCR**: 補正後の画像に Vision の `VNRecognizeTextRequest`(accurate、日本語+英語)をかけ、認識位置に透明テキストを重ねる。すべて端末内で処理し、外部サービスには送らない。実写のページで平均信頼度 0.87、本文段落は 1.00 程度。
  透明テキストのフォントサイズは行 bbox の高さそのままではなく、**隣接行との行ピッチと行幅に収まる自然幅で上限**を掛ける。写真の傾きで bbox が縦に膨らむと隣接行のグリフが重なり、PDFKit(プレビュー / Spotlight / `page.string`)が段落を 1 ブロックに誤統合して行順を入れ替えるため(pdfminer 等ストリーム順で読むツールでは元々問題ない)。
- **Markdown 書き出し**: OCR 結果をそのまま連結すると 2 段組や囲み記事(「蛇足」など)が行単位で混ざるので、**XY-cut**(余白の切れ目で縦横に再帰分割する古典的なレイアウト解析)でブロックに分けてから読み順に並べる。段落は「文末記号で終わる」「行が本文幅より短い(段落最終行・見出し・図のラベル)」「行間が大きい」で区切る。縦組みのページは列を右から左に読む。各ページの見出しには対応する PDF ファイル名とページ番号(`## p.3 — <pdf名> p.3`)を入れる。RAG(Foundry の file search など)には PDF と .md を一緒に投入し、引用の見出しから正解である PDF のページ画像へ辿れるようにするため。PDF を保存すると続けて同名の .md の保存ダイアログが出る(キャンセル可)。

### 撮影のコツ

- 三脚などでカメラを固定し、見開き全体が画面の 2 割以上を占めるようにする。紙と背景にコントラストがあると枠検出が安定する。
- 取り込まれないときは設定の「静止判定のしきい値」を上げる/「最短静止時間」を下げる。逆に手を置いただけで取り込まれるなら「最短静止時間」を上げる。
